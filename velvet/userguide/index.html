Velvet
User Guide

Create Linux and macOS virtual machines on your Mac. Use the Linux desktop and terminal, or connect a coding agent to run commands and tests.

Create a VM ↓ Connect an agent

Velvet Dev runs on Apple silicon Macs with macOS 27 or later. Linux VMs use ARM64 (aarch64) installers and disks. macOS VMs use an Apple restore image compatible with your Mac.

Create a Linux VM

Choose Ubuntu Desktop for a graphical session or Ubuntu Server for a terminal-focused environment.

  1. In Templates, select Install… beside Ubuntu Desktop or Ubuntu Server. You can also open New VM, choose Linux, and select Installer ISO.
  2. Click Get Linux… and choose Download or Use installer if it’s already cached. Use Choose… if you have your own ARM64 ISO.
  3. Name the VM, continue through Resources, Storage, and Review, then select Create machine.
  4. On the VM’s page, select Boot installer. Follow Ubuntu’s instructions inside the VM and create your Linux account. When installation finishes, shut down the VM, eject the ISO, and select Run machine.

Use an existing disk or machine

  • Import a disk copies an ARM64 .asif or RAW disk into a new VM. A bootable disk needs its own bootloader and installed system. Convert other formats, such as QCOW2, to a supported disk format before importing.
  • Open Virtual Machine… adds a Velvet VM folder to the library in place. Use it when the VM already has a Velvet configuration and disk.
  • Set up later creates a blank disk. Select Choose installer on the machine’s page when you’re ready.

Create a macOS VM

Velvet downloads restore images directly from Apple and checks whether the selected image can run on your Mac.

  1. In Templates, select macOS, then choose Install… beside a release. You can also open New VM and select macOS.
  2. Click Get macOS… and choose Download or Use installer if it’s already cached. Select Choose… to use a compatible local .ipsw file.
  3. Name the VM and review its resources and storage. On Review, select Create & Install. Velvet restores macOS to a fresh virtual disk.
  4. Wait for the VM to reach Setup Assistant, then follow the prompts in its window. Use Run machine to start the installed VM on later visits.

Two macOS VMs at a time

Starting or installing macOS uses a slot, and macOS VMs in other apps count toward the limit. If both slots are in use, shut down a macOS VM or cancel an installation before trying again. Linux VMs use neither slot.

Use prepared templates

Templates shows official installers and any prepared environments available for your Mac. If you have a signed Velvet template package, use Import Template Catalog…. Choose Create VM for a cached prepared image or Download and create… to download it first. Velvet boots an independent VM from the verified base and sets up Poppy Tools for supported Linux templates.

  1. Choose resources, a storage location, and an optional project in the creation dialog.
  2. Watch Activity for first-boot setup. Template ready means setup completed.
  3. Open the VM window when it’s ready. For supported templates, the creation dialog, machine page, and Settings → System explain how to sign in.

Ubuntu template account

The desktop or terminal signs in automatically as developer after setup. The account has no login password and direct root login is disabled. Use sudo <command> for one administrative command or sudo -i in the VM terminal for a root shell. Both use passwordless sudo. For manual installs and imported disks, use the account configured inside that VM.

Run and use the console

Choose Run machine to boot, or Show window to return to a running VM. Closing the window leaves the VM running. Use Shut down and wait for the stopped state before changing hardware settings.

Find startup output

  • VM Display shows the graphical console, including the installer and boot output sent to the display.
  • Window → Show Terminal opens the serial terminal. A terminal-oriented template can switch there when Linux starts sending serial output. Use Show VM Display to switch back.
  • In an accelerated VM, Window → Show Boot Output reopens the serial boot view. Choose Open Console Log in the library’s machine menu for the retained serial log.

Serial text depends on what the guest sends. If an imported Linux image shows a blank Terminal, switch to VM Display. To adjust serial text size, use the VM window’s Window menu. If Linux cannot shut down cleanly, Force Stop… in the machine menu cuts power and can interrupt writes.

VM settings and storage

Shut down a VM, choose Settings, then use Continue to reach the relevant step. Finish with Save changes on Review. The changes apply at the next start.

StepWhat you can change
SystemName and installation media.
ResourcesVirtual CPUs, guest memory, shared networking, display resolution, and graphics.
StorageFolder location and disk expansion. After increasing virtual capacity, extend the partition or filesystem in Linux if the guest requires it.
ReviewConfirm the resulting configuration and save it.

Display resolution can be Automatic, Match Window, or a fixed size. Match Window requests the Mac window’s pixel size, including Retina. Linux can keep its current mode until you select the new resolution in the guest. The networking switch uses a shared connection through your Mac.

On the machine page, Disk capacity is what the guest can use. Allocated on this Mac shows the disk’s allocated blocks. A growable disk consumes host space as the guest writes data. Use Reveal in Finder to locate the VM folder. From Remove…, choose Remove from Library to keep its files, or Move to Trash for a stopped VM you intend to delete.

Linux 3D acceleration

Test hardware-accelerated OpenGL in an Ubuntu desktop VM.

  1. Start the VM with Standard graphics. Install and pair Poppy Tools so the accelerated window can deliver mouse and keyboard input.
  2. Shut down the VM. Open Settings → Resources and change Graphics to Accelerated OpenGL.
  3. Review the GPU memory limit and select Save changes. Start the VM and open its desktop.
  4. In Linux, run glxinfo -B with Mesa utilities installed. Look for direct rendering and a virgl renderer. Run a Linux OpenGL app in the desktop to try acceleration.

Use Advanced graphics to choose the renderer placement. Isolated is the default and runs the renderer in a separate process. If the desktop or input is unavailable, switch the stopped VM back to Standard and check Poppy Tools.

Install Poppy Tools

Tools connects Linux to Velvet for supervised commands and accelerated-window input. A ready Ubuntu template VM already has Tools. For a manually installed or imported Linux VM, pair it from its machine page.

  1. Shut down the VM, then select Poppy Tools → Set up Poppy Tools….
  2. Choose Prepare installation disk. Start the VM and sign in to Linux.
  3. Copy the command from the setup sheet and run it inside the guest as root. Use your Linux account’s usual method for obtaining administrative access.
  4. Return to the library and look for Connected in Poppy Tools. The service reconnects automatically after boot. Reconnect retries an existing pairing.

The installation disk contains this VM’s pairing key. Keep it private. Use Forget connection… on a stopped VM to revoke the pairing. To reconnect a VM whose Tools are outdated, follow Installation help… to pair and install the current Tools.

Run commands from Velvet

On a running VM with Tools connected, select Run command…. Pick a Linux account, enter an existing absolute guest working directory, and choose the time limit. Allow commands grants the selected account command access for four hours. Commands use that account’s Linux permissions and configured privileges.

For a first check, enter uname -r with / as the working directory. Every run starts a fresh, noninteractive shell. Use the VM terminal for commands that need input, a login shell, or an interactive program.

Open the machine’s Commands panel to see task state and switch between Standard output and Errors. Review the exit code and use Save output… to keep the retained output. History remains available with the VM shut down. Stop requests can interrupt running work. They cannot undo writes that already happened.

Connect coding agents through MCP

Use a local MCP connection to let Codex, Claude Code, or another client discover VMs and run work in Linux.

  1. Select Automation → Connect agent and choose your client.
  2. Choose Copy setup message, then paste it into that agent and send it. The message registers the protected local connection and supplies the Velvet skill.
  3. Ask the agent to list my Velvet VMs to verify access in that chat. If the MCP client needs a restart or reconnect, do that and repeat the read-only check.
  4. To reuse a VM, install Tools and choose Add existing VM… from the connection details. Select the intended account and Allow access. Adding a VM grants only that selected VM and Linux account.

Try an agent request

“Run uname -r in my Ubuntu VM and show the kernel version.” For a build or test request, tell the agent which VM and which Linux workspace to use. Make sure the source is already inside Linux.

Setup verified records successful contact. To check a particular chat, run the list request there. Use the connection’s Settings to manage its resource and storage limits. Remove access revokes one VM grant. Remove connection revokes the client and schedules cleanup of its temporary VMs.

The local MCP tools cover template provisioning, VM lifecycle, project metadata, and batch execution. Use the native VM window for interactive terminal and desktop work. The local setup authenticates through Velvet’s protected configuration, with no Linux password or SSH setup required.

Projects and temporary VMs

Use Projects → New Project to name a workflow and record an absolute Linux workspace path. Bind an existing VM from the project page, or choose the project when creating a template VM. The binding records a path inside Linux. Create the directory and put your source there separately.

Choose Temporary when a template VM is disposable. A temporary VM normally expires after one hour, including setup and time spent shut down. Extend 1 Hour adds time within the connection’s limits. Keep makes it persistent. Save work you want to keep before using Release…, which deletes the managed VM after safe shutdown.

Command line and MCP tools

Run the bundled CLI

In macOS Terminal, use the executable from the installed Dev app. Adjust the path if you keep the app outside Applications. Choose external VM folders in Velvet first so the sandbox can restore its saved access.

velvet="/Applications/Poppy Velvet Dev.app/Contents/MacOS/velvet-dev-library"
"$velvet" --cli --help
"$velvet" --cli status "/path/to/Ubuntu.virtio"
"$velvet" --cli start "/path/to/Ubuntu.virtio" --window
"$velvet" --cli console "/path/to/Ubuntu.virtio"
"$velvet" --cli shutdown "/path/to/Ubuntu.virtio"

Use Ctrl+] to detach from the CLI console. The CLI help also lists disk and display configuration, Tools setup, task output, and diagnostics. Guest paths passed to exec --cwd must already exist inside Linux.

GoalTools and results

The tools and limits exposed by each MCP connection appear in its live discovery. Use the bundled Velvet skill for detailed examples and operation recovery.

Troubleshooting

The VM returns to its installer.
Shut down, eject the ISO from Installation media, then boot the system disk.
The terminal has no boot messages.
Switch to VM Display to see the graphical console. Check Open Console Log for serial output the guest has emitted.
The accelerated desktop shows Input needs Poppy Tools.
Check the Tools connection. If you need working input to install Tools, switch the stopped VM back to Standard, install and pair Tools, then re-enable acceleration.
A VM folder is unavailable.
Reconnect its drive and choose Open Virtual Machine… to select its folder and restore access.
The agent can’t see a VM.
Check that MCP lists VMs in that chat, the connection still grants that VM, its Tools are connected, and the intended Linux account is selected.
The VM failed to start or shut down.
Open View diagnostics… from the machine. For a reproducible launch problem, use Run with diagnostics, then Export diagnostics… to save a report.
